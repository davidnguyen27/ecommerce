## Quyết định khi triển khai

- `e2e/tests/reports.spec.ts` gồm hai kịch bản.
- **Kịch bản 1:**
  - khách mua và trả qua UI; đơn được chuẩn bị, bàn giao và giao qua API quản trị;
  - owner mở Báo cáo từ menu, thấy "Doanh thu thuần" khớp API cho tháng này;
  - đổi kỳ sang tháng trước, thấy số khớp API cho tháng đó;
  - bấm "Xuất Excel", tải được file đúng tên.

  Kịch bản so với API chứ không với số cố định, vì các spec khác cũng giao đơn trên cùng stack.
- **Kịch bản 2:** kế toán thấy khối "Cần xử lý" và mục menu Báo cáo; nhân viên kho không thấy cả hai.
- **Helper mua hàng chung:** `buyAndPay` và `ensureSellable` được tách từ `refund.spec.ts` sang `e2e/support/purchase.ts`. Hai spec dùng chung, phân biệt khách bằng `tag` và `suffix`.
- Chạy cả bộ E2E trên stack smoke (Edge): 11/11 pass.
